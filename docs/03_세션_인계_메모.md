## 1-A. 실사용 1주 뒤 반영한 것 (이번 세션)

사용자가 보고한 불만 두 개를 받아 고쳤다. 둘 다 "짐작으로 먼저 만들지 말 것"을
지킨 결과 - 일주일 써 보고 나온 실제 불편이다.

### (1) 장소를 좌표 없이 추가 [F-19]

`GET /api/geocode?q=&lat=&lon=` · `nowbus search` · 앱의 '장소 추가' 화면(세 번째
화면). `nowbus place add 집` 처럼 좌표를 생략하면 검색 결과에서 번호로 고른다.

공급원 두 개를 **번갈아** 담는다 (`providers/geocode.py`).

- `StopGeocoder` — DB 의 정류장 12,897곳 이름. 키도 네트워크도 필요 없다. **항상 켜짐.**
- `KakaoGeocoder` — `NOWBUS_KAKAO_REST_KEY` 가 있을 때만. 건물·상호·주소.

**⚠️ 카카오 파싱은 실물 응답으로 확인하지 못했다.** `dapi.kakao.com` 이
개발 컨테이너에서 403 으로 막혀 있다(버스 API 와 같은 정책). 문서만 보고 썼고,
방어적으로 파싱하며(없는 키는 건너뛴다) 로컬 확인 경로를 만들어 뒀다:

```zsh
python scripts/smoke_geocode.py "강남역 스타벅스"
```

원본 응답을 `tests/fixtures/{keyword,address}_kakao.json` 에 저장한다. 필드명이
다르면 **픽스처를 보고 `_parse_kakao()` 를 고칠 것. 추측으로 고치지 말 것** (§3 과
같은 이유). `tests/test_geocode.py` 의 샘플은 손으로 만든 것이라 '문서대로 오면
이렇게 읽는다'까지만 증명한다.

정류장 좌표를 장소로 저장하면 도보 시간이 0 에 가깝게 잡혀 판정이 무의미해진다.
CLI 와 앱 모두 `source == "stop"` 일 때 경고한다. 지우지 말 것.

### (2) 1~2분 뒤 도착 버스 — RUN 등급 [F-20]

불만 원문: *"충분히 뛰어서 정류장까지 도착할 수 있는데 이런게 안나오면 결국
네이버를 다시 찾아볼 수 밖에 없게 돼."*

원인은 `pick_boardable()` 이 걷기 기준 MISS 를 건너뛰고 다음 차를 고르는 것이었다.
버그가 아니라 설계대로였고, 등급이 하나 없었던 것이다.

- `Catch.RUN` 추가 — TIGHT 와 MISS 사이. 걸어선 늦지만(margin<0) 뛰면 닿는다.
- `pick_sprint()` 를 **따로** 만들었다. `pick_boardable()` 에 섞지 않은 이유:
  1분 뒤 차(뛰면 잡음)가 9분 뒤 차(여유 있음)를 가려버린다. 둘은 서로를 대체하지
  못하므로 양쪽 다 살아 있어야 한다.
- `plan_now()` 가 `PlanSet(best, sprint)` 를 돌려준다. **랭킹(§6.4.1)은 손대지
  않았다** - 점수로 합치면 벌점 없이는 뛰는 후보가 화면을 독점하고, 벌점을 얹으면
  상위 5개에서 밀려 아예 안 보인다(실사용에서 후자였다).
- 필터 하나: 걸어서 잡는 최선보다 총 소요시간이 짧지 않으면 뛰는 후보를 버린다.
  뛰어서 얻는 게 없으면 뛸 이유가 없다. `best` 가 비었을 때는 전부 남긴다.
- 상한: `MAX_RUN_MIN=3.0` 분. `RUN_SPEED=140 m/min`. **둘 다 추정값이다**
  (D-11·D-12). 신호등 대기는 모델에 없다.

응답의 `sprint` 와 `items` 는 **같은 정류장·노선이 겹칠 수 있다.** 버그가 아니다 -
'뛰면 2분 뒤 차 / 안 뛰면 12분 뒤 차' 가 둘 다 사실이다.

곁가지로 하나 고쳤다: `PlanItem.is_estimated` 가 스키마에는 있는데 `_to_item()` 이
채우지 않아 '배차간격 추정' 태그가 한 번도 뜨지 않았다. 이제 `Plan` 이 들고 간다.

### 검증 방법

목 Provider + Chromium 으로 세 화면을 확인했다. 스크린샷 경로는 세션 스크래치라
남지 않지만, 재현 방법은 이렇다 (`playwright` 는 pip 로 따로 깔아야 한다):

- `webapp.build_provider` 를 목으로 갈아끼운 뒤 `create_app()` 을 부른다.
  **`app.state.provider` 에 직접 넣으면 lifespan 이 덮어쓴다** - 테스트가
  lifespan 을 안 타서 지금까지 문제가 없었을 뿐이다.
- Chromium 실행 경로는 `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`.
- localhost 로 curl 할 때는 `NO_PROXY=127.0.0.1` 을 붙인다. 안 붙이면 에이전트
  프록시를 타면서 "Invalid HTTP request" 가 난다.

## 2. 사용자가 잡아준 것 — 같은 실수 반복하지 말 것

이 대화에서 **내가 두 번 틀렸고 두 번 다 사용자가 잡았다.** 둘 다 "그럴듯한
추론"이 실제 데이터와 달랐던 경우다. 새 세션도 같은 함정에 빠지기 쉽다.

### 2-1. `direction` 조인 (내가 넣었다가 되돌림)

`route_stop.direction` 이 행선지 종점명이라는 걸 알고, "회차 지점을 넘는
조합은 종점까지 갔다 와야 한다"고 **잘못 추론해** §9.1 질의에 조인을 걸었다.

사용자 지적: *"강남역9번출구에서 타면 진흥아파트, 서초푸르지오써밋,
신논현역 지나서 강남역1번출구 도착하는데, seq 66에서 70이면 4정거장 뒤인데
왜 상계동 종점에 가야 한다는 거지?"*

맞는 지적이었다. 데이터를 다시 보니 회차점은 종점이 아니라 **노선 한복판**
(기점에서 가장 먼 seq 67, 18.4km)이고 seq 135는 기점으로 돌아온다. 차량은
seq 1→N 을 연속으로 달리고 `direction` 은 앞 행선판이 바뀌는 것뿐이다.

→ 조인 제거. 조건은 `rs2.seq > rs1.seq` 하나.
→ `test_turnaround_point_is_mid_route_not_the_terminal` 이 전제를 고정한다.
**이 테스트를 지우거나 direction 조인을 되살리지 말 것.**

### 2-2. 후보 상한을 조합 탐색 *전에* 적용

`MAX_ORIGIN_STOPS=8` 을 거리순으로 먼저 잘랐다. 실데이터에서 드러났다:
강남역 반경 600m 정류장 39곳 중 시청행 직통이 있는 곳은 8곳뿐인데 거리순
상위 8곳과 거의 겹치지 않는다. 먼저 자르면 노선 9개 중 1개만 남았다.

→ 조합을 먼저 찾고 '직통이 있는 승차 정류장' 중에서 자른다.
→ 하차 쪽 상한(`max_dest_stops`)은 외부 호출이 없어 제거했다.
**config 에 다시 추가하지 말 것.**

### 교훈

픽스처 한 노선(146번)으로는 못 잡는 종류의 버그였다. **실데이터로 한 번
돌려보는 것**이 테스트보다 먼저 잡아낸다.

## 4. 환경 — 이걸 모르면 헤맨다

### 개발 컨테이너 (Claude Code 가 도는 곳)

**외부 API 가 조직 이그레스 정책에 막혀 있다.**
`ws.bus.go.kr`, `apis.data.go.kr`, `data.go.kr`, `data.seoul.go.kr` 전부 403.
**`dapi.kakao.com`(카카오 로컬)도 마찬가지로 CONNECT 거부된다** — 장소 검색을
붙이면서 확인했다. `nominatim.openstreetmap.org` 도 막혀 있다.

- `scripts/smoke.py`, `scripts/smoke_geocode.py`, `nowbus plan` 은 **여기서 실행
  불가**. 로컬에서만 된다.
- 테스트 136개는 전부 오프라인(픽스처 기반)이라 여기서 돈다.
- 프론트 확인은 목 Provider + Chromium 으로 했다.
  Playwright 는 pip 버전이 달라 `executable_path="/opt/pw-browsers/chromium-1194/chrome-linux/chrome"`
  를 줘야 한다. `playwright install` 은 실행하지 말 것.

### 사용자 로컬

**macOS (zsh).** 세션 초반엔 Windows(cmd)였다가 중간에 맥으로 옮겼다.
Windows 전용 명령(`winget` 등)을 주지 말 것.

배포는 **D-9 = A안(집 PC + 터널)** 으로 확정. 다만 Cloudflare Tunnel 이
아니라 **Tailscale Funnel** 을 쓴다:

- `trycloudflare.com` URL 은 재시작마다 바뀌어서 홈 화면 아이콘이 죽는다.
  "아침에 아이콘 한 번 탭"이라는 MVP 완료 정의와 맞지 않는다.
- Tailscale Funnel 은 도메인 없이 `https://<맥>.<tailnet>.ts.net` 고정 주소를
  무료로 준다. `brew install --cask tailscale-app` (CLI 전용
  `brew install tailscale` 은 데몬이 root 를 요구해서 막힌다).

### 매일 아침 돌아가야 하는 것

```zsh
tailscale funnel --bg 8000     # 한 번만. 재부팅해도 유지
caffeinate -s nowbus serve     # 이건 계속 떠 있어야 함
```

- 화면 잠김·디스플레이 꺼짐은 괜찮다. **시스템 잠자기**가 서버를 죽인다.
- `caffeinate -s` 는 전원 연결 시에만 유효하고 **뚜껑 닫기는 못 막는다.**
- launchd 자동 실행은 만들자고 제안했으나 사용자가 "일단 써보고" 로 보류.

일주일 실사용 후 보고받기로 한 것 중 **아직 안 받은 것**:

- 도보 예상 vs 실제 (→ `WALK_DETOUR` 1.30, `CALIB`)

- 5개가 한 정류장에 몰리는지 (→ **D-10**)

이번에 추가로 물어볼 것:

- **RUN 후보를 보고 실제로 뛰어서 탔는지** (→ D-11 `RUN_SPEED`, D-12 `MAX_RUN_MIN`).
  못 탔다면 어디서 잃었는지 - 신호등이면 속도를 낮추는 게 아니라 고정 페널티를
  넣어야 한다.
- **장소 검색으로 찾으려던 곳이 안 나온 사례** (→ 카카오 키를 넣었는지부터 확인).
- `scripts/smoke_geocode.py` 를 돌렸는지. 안 돌렸으면 카카오 파싱은 여전히 미검증이다.

> 안 알려준 것 같지만 넘어가자"고 했다. MVP 완료 정의의 절반은 충족됐다.

## 8. 작업 스타일

사용자 선호(설정에 등록돼 있음):

- **한국어**, 주로 Python
- **설명은 핵심만 확실히.** 장황한 나열보다 결론과 근거
- **모르는 건 모른다고.** 웹 검색으로도 확인 안 되면 추측하지 말고 그렇게 말할 것

이 대화에서 실제로 잘 작동한 방식:

- 데이터 모양이 의심되면 **추측하지 말고 실물을 받아서 확인**한다
- 사용자가 반론하면 **먼저 데이터를 다시 본다.** 두 번 다 사용자가 옳았다
- 작업 단위마다 커밋하고, 커밋 메시지에 **왜 그렇게 했는지**를 남긴다
  (특히 계획서와 다르게 간 경우)
- 사용자가 로컬에서 할 일과 컨테이너에서 할 일을 명확히 나눠서 안내한다
